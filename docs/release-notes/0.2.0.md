# Asterism 0.2.0

Asterism 0.2 adds a supported Python interface for fitting one censored trait
with several covariance components. The one-component censored model remains
available on its unchanged numerical path.

## What changed

`CensoredComponentModel` takes the component relationship matrices and
fixed-effect design once, then accepts the measured values, censoring indicators
and instrument limits at each call.

- `fit` reports every component coefficient and its scale-invariant
  mean-diagonal proportion.
- `interval` profiles the mean-diagonal proportion by default, or the raw
  coefficient when explicitly requested.
- `test` tests whether one component is nought. With several components it
  labels the reference `asymptotic_mixture_50_50` and refuses when another
  component or the residual rests on its bound.

There is deliberately no generic `heritability` field. The first supplied
matrix is not necessarily additive kinship, and its raw coefficient changes
when that matrix is rescaled. When the first component is additive kinship,
`mean_diagonal_proportions[0]` is the comparable quantity.

`grouping_matrix` now builds a relationship matrix from shared group labels,
including household and person-level components. The shared normal-probability
calculation is also more accurate in highly correlated and deep-tail cases, and
relationships of one are accepted. This permits monozygotic-twin and explicit
person-level components rather than rejecting them at construction.

The manifest analysis name `one_trait_tobit_audiogram` has changed to
`one_trait_censored`, because the model is not specific to hearing. Seven
bivariate numerical error codes have also lost their
`LATENT_MEDIATION_` prefix, and the three model-specific
`*_RELATIONSHIP_TOO_CLOSE` codes are retired with the former relationship
guard. See the [changelog](../../CHANGELOG.md) for the exact names.

## The several-component test and its limit

The several-component test is an explicitly asymptotic calculation, not a
finite-sample guarantee. On the fixed-instrument, 1,909-person,
four-component target it rejected 0.055 of null datasets at 52% expected
censoring, but 0.095 at 75%; the latter failed its declared nominal 0.05 rule.
For that exact higher-censoring analysis, the analytic p-value must not be
reported without a design-specific simulated null tied to the model, design,
source and seed.

This is not a universal censoring threshold. It does not disable the labelled
asymptotic test for other designs, and it does not affect fitting or intervals.
The one-component target remained clean, with null rejection rates of 0.040
and 0.045 at 52% and 75% expected censoring respectively.

`CensoredComponentModel.bootstrap` can simulate the constrained-null
distribution and now refits its deterministic, independent draws in parallel.
It remains experimental rather than a supported 0.2 quantity. The completed
200-by-999 target campaign passed with no failed attempt: all 800 requested
draws were measured, null rejection was 0.055 at 52% and 0.060 at 75% expected
censoring with each exact interval containing the nominal 0.05, and interval
coverage was 0.980 and 0.960 against a lower-end 0.975. That supplies, at that
exact design and no further, the design-specific simulated null the limitation
above requires.

## Evidence and qualification

Retained fixed-instrument evidence already supports the independent numerical
comparison and several-component interval coverage. Across the independent
full-fit comparison, the largest mean-diagonal proportion differences were
0.0014 and 0.0029 at expected censoring shares of 25% and 50%. In the interval
campaign, all simultaneous exact intervals contained the declared nominal
coverage and there were no refusals. The exact target-test failure above is
retained as a known limitation rather than hidden or converted into a portable
design rule.

The corrected component-separation campaign also passed. It requested 200 fits
at each combination of 30 or 60 sibling pairs and 52% or 75% expected
censoring, using two records per person and the paper's six fixed-effect
columns. There were 799 available fits out of 800. At 60 families the estimated
additive/person-level shares were 0.3759/0.2996 and 0.3675/0.2936 against truths
0.4/0.3; both cells passed the predeclared bias rule. The split was about three
times less precise than the combined component at both censoring levels.

The release bundle retains the full scientific release run, one standard
synthetic receipt per supported analysis, the four-way macOS/Linux and Python
3.13/3.14 comparison, and the installed manylinux-wheel smoke from Medusa. Its
`SHA256SUMS` binds both wheels and the evidence archive to those results.

## Installation and artefacts

Download the wheel for your platform from the GitHub release and install that
exact immutable artefact rather than a development checkout:

```sh
# macOS on Apple silicon
python -m pip install ./asterism-0.2.0-cp313-abi3-macosx_11_0_arm64.whl

# Linux on x86-64
python -m pip install ./asterism-0.2.0-cp313-abi3-manylinux_2_17_x86_64.manylinux2014_x86_64.whl
```

The PyPI distribution named `asterism` is unrelated software; Asterism 0.2.0
is distributed through its checksummed GitHub release wheels.

Asterism 0.2.0 supports GIL-enabled CPython 3.13 and 3.14 through two ABI3
wheels:

- `asterism-0.2.0-cp313-abi3-macosx_11_0_arm64.whl`
- `asterism-0.2.0-cp313-abi3-manylinux_2_17_x86_64.manylinux2014_x86_64.whl`

The release page carries those wheels, `release-evidence.tar.gz` and
`SHA256SUMS`.
